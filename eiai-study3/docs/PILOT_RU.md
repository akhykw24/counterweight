# Пилот на 5 человек — инструкция

Для человека без технических знаний. Всё, что нужно, — браузер и доступ к
Supabase.

---

## 1. Ссылки для участников

Каждому участнику — **своя ссылка**. Отличается только цифра в конце.

| Участник | Ссылка |
|---|---|
| 1 | `https://counterweight-pearl.vercel.app/?pilot=true&p=1` |
| 2 | `https://counterweight-pearl.vercel.app/?pilot=true&p=2` |
| 3 | `https://counterweight-pearl.vercel.app/?pilot=true&p=3` |
| 4 | `https://counterweight-pearl.vercel.app/?pilot=true&p=4` |
| 5 | `https://counterweight-pearl.vercel.app/?pilot=true&p=5` |

**Зачем разные цифры.** Они определяют, какую версию советчика человек увидит:
тёплую или нейтральную. Цифры чередуются, поэтому при пяти участниках обе
версии гарантированно будут представлены. Если раздать всем одинаковую ссылку,
версии распределятся случайно — и есть заметный шанс, что все пятеро попадут в
одну группу, а пилот проверит только половину исследования.

**Не давайте двум людям одну цифру.** Тогда они попадут в одну версию, и баланс
пропадёт. Если участник потерял ссылку — дайте ему ту же самую цифру, что была,
версия не изменится.

**Что видит участник.** Ровно то же, что увидят настоящие участники, плюс три
необязательных вопроса в самом конце — про то, было ли что-то непонятно, сколько
времени заняло и о чём, по их мнению, исследование. Отвечать не обязательно.

**Сколько занимает.** Около 15 минут.

## 2. Как проверить, что ответы дошли

Откройте Supabase → ваш проект → **Table Editor** → таблица `events`.
Или через **SQL Editor** — так нагляднее:

```sql
select run_mode, count(distinct session_id) as people, count(*) as events
from public.events
group by run_mode;
```

Должно получиться примерно так:

| run_mode | people | events |
|---|---|---|
| pilot | 5 | ~900 |
| test | … | … |

- **`pilot`** — ваши пилотные участники. Здесь и смотрите.
- **`test`** — технические прогоны, мои и ваши. В анализ не идут.
- **`live`** — настоящее исследование. Пока пусто, и так и должно быть.

### Дошёл ли конкретный человек до конца

```sql
select session_id,
       min(received_at) as started,
       count(*) filter (where type = 'ESTIMATE_FINALIZED') as answered,
       count(*) filter (where type = 'SESSION_COMPLETED') as finished
from public.events
where run_mode = 'pilot'
group by session_id
order by started;
```

- `answered` = **12** — человек прошёл все задания.
- `finished` = **1** — дошёл до конца, включая дебрифинг.
- `answered` меньше 12 — бросил на середине. Это нормальный результат пилота:
  важно понять, на каком месте.

### Кто в какой версии оказался

```sql
select payload->>'condition' as version, count(*) as people
from public.events
where run_mode = 'pilot' and type = 'ALLOCATED'
group by version;
```

Должны быть обе строки: `warm` и `neutral`.

## 3. Как выгрузить пилотные данные

В **SQL Editor** выполните и нажмите **Download CSV** (или **Export → JSON**):

```sql
select event_id, session_id, seq, client_ts, type, payload, run_mode
from public.events
where run_mode = 'pilot'
order by session_id, seq;
```

Сохраните как `data/pilot-events.jsonl` в папке `eiai-study3` — по одному
объекту на строку. Затем в терминале, из папки `eiai-study3`:

```bash
python pipeline/replay.py --events data/pilot-events.jsonl --out data/pilot-tables
```

Появятся таблицы в `data/pilot-tables/`: по участникам, по заданиям, по анкете.
Их можно открыть в Excel.

**Важно.** Полный анализ (`analysis.py`) на пилотных данных **не запустится**, и
это сделано намеренно: он удаляет всё, что не помечено `live`, ещё до первого
расчёта. Пилот нужен, чтобы проверить процедуру, а не чтобы получить результат.
Смотрите на таблицы, а не на статистику.

### Ответы на три финальных вопроса

```sql
select payload->>'question' as question, payload->>'text' as answer
from public.events
where run_mode = 'pilot' and type = 'PILOT_FEEDBACK'
order by received_at;
```

Это главное, ради чего пилот и проводится.

## 4. Если участник пишет об ошибке

**Сначала спросите три вещи:**

1. Телефон или компьютер? Какой браузер?
2. На каком экране это случилось — что было написано сверху?
3. Что именно произошло: белый экран, кнопка не нажимается, текст не помещается?

**Что можно ответить сразу:**

| Жалоба | Что сказать |
|---|---|
| «Страница перезагрузилась / я случайно закрыл вкладку» | Пусть откроет **ту же ссылку** снова. Исследование продолжится с того же задания, ничего не потеряно. |
| «Пропал интернет» | Ничего не потеряно. Ответы сохраняются в браузере и уходят на сервер, когда связь вернётся. Пусть просто продолжает. |
| «Не могу двинуть ползунок» | Нужно нажать на полосу или потянуть кружок. Значение появится справа от полосы. |
| «Я передумал участвовать» | На последнем экране есть кнопка **Delete my answers from the study**. После неё ответы не идут в исследование. |
| «Мне нет 18 / плохо знаю английский» | Это нормально: исследование само не пускает дальше первого экрана. Данные при этом не собираются. |

**Чего делать не нужно:** просить участника что-то чинить или проходить заново
«на всякий случай». Повторное прохождение одним человеком портит данные сильнее,
чем незавершённая сессия.

**Проверить, потерялись ли данные**, можно запросом из раздела 2. Если сессия
человека там есть и `answered` больше нуля — данные дошли, что бы ни случилось
на экране.

## 5. Когда пилот закончится

1. Соберите ответы на три финальных вопроса (раздел 3).
2. Посмотрите, все ли дошли до конца и где останавливались.
3. Напишите мне, что нужно поправить.

**Пилотные данные не войдут в исследование** — они помечены `pilot` и
отбрасываются автоматически, до всякого расчёта. Это не потеря: пилот проверяет
процедуру, а не гипотезу.
