# Deploying Counterweight to Vercel

Production runs on **PostgreSQL** (Neon or Supabase) because Vercel's serverless filesystem
is ephemeral — SQLite would reset on every cold start/deploy. Local dev keeps **SQLite** via
an auto-derived schema.

## How the two databases are wired
- `prisma/schema.prisma` — the canonical **PostgreSQL** schema. Used by Vercel and any
  Postgres command. `url` is a pooled connection (app runtime); `directUrl` is a direct
  connection (schema pushes / migrations).
- `prisma/schema.sqlite.prisma` — **auto-derived** local SQLite schema (gitignored).
  Regenerated by `scripts/make-sqlite-schema.mjs` whenever you touch `schema.prisma`.
- Both use `prisma db push` (no migration files).

> Prisma's datasource `provider` can't be set from an env var — it must be a literal — which
> is why there are two schema files instead of one env-switched schema.

## Local development (SQLite)
```bash
npm install
npm run db:push:sqlite   # creates/updates ./prisma/dev.db from the derived schema
npm run dev              # predev derives the schema + generates the SQLite client
```
`.env` keeps `DATABASE_URL="file:./dev.db"`; API keys (`GEMINI_API_KEY`, `GROQ_API_KEY`) live
in `.env.local`.

## Production deploy (Postgres + Vercel)

### 1. Create a hosted Postgres and copy two connection strings
- **Neon:** `DATABASE_URL` = the **pooled** string (host contains `-pooler`); `DIRECT_URL` =
  the **direct** string (no `-pooler`). Append `?sslmode=require` if not already present.
- **Supabase:** `DATABASE_URL` = port **6543** with `?pgbouncer=true`; `DIRECT_URL` = port
  **5432**.

### 2. Push the schema to the hosted DB (one-time, from your machine)
PowerShell:
```powershell
$env:DATABASE_URL="<pooled url>"; $env:DIRECT_URL="<direct url>"; npx prisma db push
```
bash:
```bash
DATABASE_URL="<pooled url>" DIRECT_URL="<direct url>" npx prisma db push
```
This targets the default Postgres `schema.prisma`. Re-run whenever the schema changes.

### 3. Set Vercel environment variables
Project → Settings → Environment Variables (Production + Preview):
`DATABASE_URL` (pooled), `DIRECT_URL` (direct), `GEMINI_API_KEY`, `GROQ_API_KEY`.

### 4. Deploy
Push to GitHub and Import the repo in Vercel (Next.js auto-detected), or run `npx vercel --prod`.
Vercel runs `npm install` → `postinstall: prisma generate` (Postgres client, including the
`rhel-openssl-3.0.x` engine) → `next build`. The DB schema was created in step 2, so there's
no DB work at build time.

## Notes
- `db push` keeps no migration history — fine for the MVP. For the real study, switch the
  Postgres side to versioned migrations (`prisma migrate`) to protect participant data.
- `lib/db.ts` needs no changes: Prisma 6 connects to Postgres via its bundled engine (no
  `pg` / native driver adapter), so this environment's blocked native-install scripts don't
  matter.
